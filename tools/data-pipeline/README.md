# Scientific data pipeline

P1 provides an offline validator and reviewed transcription workflow. It does not scrape NASA pages or call ephemeris APIs from the render loop.

1. Retrieve and review primary data sources.
2. Record selected source fields in `data/sources` with URL and snapshot identity.
3. Normalize catalog values with explicit units, provenance and preserved uncertainties.
4. Validate schemas, reference graphs and conversions.
5. Generate JSON Schemas and SHA-256 manifests using `npm run data:refresh`.
6. Review the changed records/checksums; run `npm run data:validate` and `npm run check`.

`data:validate` never repairs checksums automatically. `data:refresh` is an explicit maintenance action after input review. Source and catalog versions must be updated for future data releases. The hash manifest covers catalog, source/asset manifests, exported schemas and local evidence files. Paths may not escape the repository.

The runtime validator implements only the keyword vocabulary generated by `packages/catalog/src/schema.ts` (type, const, enum, anyOf, properties, required, additionalProperties, items, minItems, minLength, pattern, numeric limits). It is not an arbitrary JSON Schema engine. Exported schemas target Draft 2020-12 and can be consumed by external conforming validators. Structural and cross-record validation are both required; JSON Schema alone cannot validate ancestry or source links.

P6 adds precision data acquisition, sample validation and provider metadata; those capabilities are not claimed in P1.
