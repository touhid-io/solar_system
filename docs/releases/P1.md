# P1 — Scientific Data Contract

## Delivered

- Versioned TypeScript and exported Draft 2020-12 JSON Schemas for catalog, source and asset manifests.
- Runtime structural and semantic validators with path-specific diagnostics.
- Nineteen NAIF-bound identity records: Sun, eight planets, Moon, nine coordinate barycenters.
- Eight sourced mean radii and masses with preserved source uncertainties and explicit kg conversion.
- Two official source records with selected-column transcriptions and SHA-256 integrity manifests.
- Stable ID, ancestry, coordinate center, barycenter, physical unit, epoch, rotation, uncertainty, missing-value and coverage contracts.
- Reviewed-license/checksum contracts for future visual/ephemeris assets (none distributed in P1).
- Offline data validation in `npm run check` and developer refresh command.
- English catalog summary in the explorer; scene remains the P0 illustrative preview.

## Validation

Type checks, contract/clock tests, offline source conversion and checksum validation, and production build are required. Negative cases cover wrong units, nonfinite numbers, duplicate IDs, dangling references, graph cycles, omitted fields, display fields entering science records, uncertainty mismatch, invalid calendar dates, incomplete completeness declarations, invalid orbital bounds and unreviewed assets. Selected source-column conversions are checked independently against transcription records.

The local pipeline is also checked by temporarily changing a checksummed source file and an Earth physical value, verifying rejection, then restoring original bytes. Evidence of successful commands is recorded in the PR.

## Limits and delivery

The starter is intentionally partial. This phase defines and validates data contracts, not orbital calculations, a full moon census or scientific positioning. Unknown Sun/Moon physical values, GM, orbit and rotation remain null. No UTC/TDB conversion, external API scraping or asset downloading runs in the browser. Interactive browser/mobile visual QA remains unperformed because no browser binary is available in this environment.

P0's PR remains open; P1 is stacked on its foundation branch so the P1 diff stays reviewable. P0 remote CI failure has no available steps/logs through the connector and remains unresolved. Local checks are reported separately from remote CI. Vercel hosting is planned after project completion; the user does not need a local developer setup.
